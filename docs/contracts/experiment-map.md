# Experiment Map Contract

## 1. Purpose

This contract defines the experiment map handoff between trimmed blocks and
canonical evidence extraction.

## 2. Scope

Covered:

- experiment scopes generated by `results_scope_mapper`;
- block-id grouping for explicit scientific contexts;
- packet membership for canonical evidence extraction;
- unmapped block reporting.

Not covered:

- evidence extraction;
- result interpretation;
- population, intervention, comparator, outcome, direction, dose, duration, or
  statistics extraction;
- downstream synthesis.

## 3. Guarantees

- The mapper consumes trimmed `blocks` only.
- The mapper does not consume metadata, paper title, section registry, batch
  state, or external knowledge.
- The mapper groups blocks into the broadest explicit scientific contexts
  supported by the provided blocks.
- The mapper preserves traceability through block identifiers.
- Each experiment scope becomes one downstream extraction packet.
- `source_block_ids` is the authoritative packet membership.
- The mapper must include every block needed to preserve the broad scientific
  context for the packet extraction pass.
- The mapper defaults to fewer, broader scopes. Splitting requires an explicit
  hard boundary such as independent studies, experiments, cohorts, datasets,
  organisms, model systems, protocols, or clearly separated method/result
  chains.
- A block may appear in zero, one, or multiple experiment scopes.
- The mapper must not modify block content.

## 4. Schema

Prompt output:

```json
{
  "experiment_scopes": [
    {
      "source_block_ids": ["string"]
    }
  ],
  "unmapped_block_ids": ["string"]
}
```

The prompt output only permits `source_block_ids` per scope. Runtime validation
must drop legacy mapper fields such as `scope_label`, `scope_kind`, and
`scope_basis` before persisting `experiment_map.json`.

The persisted output preserves the prompt output envelope after validation. It
does not add `paper_id` or `experiment_id`; the map organizes block ids only.

`experiment_packets.json` is derived deterministically from this map and the
trimmed blocks. It is not a separate LLM output.

## 5. Invariants

- `source_block_ids` and `unmapped_block_ids` must reference existing block ids.
- Each scope with `source_block_ids` creates exactly one downstream packet.
- Packet blocks must be exactly the blocks referenced by `source_block_ids`, in
  the same order.
- Different outcomes, measurements, tables, figures, subgroups, timepoints,
  doses, statistical tests, quantitative values, or result directions are soft
  boundaries and must not cause packet splitting by themselves.
- Legacy `scope_label`, `scope_kind`, and `scope_basis` values must not be
  retained in persisted experiment maps or downstream packets.
- Missing or uncertain scientific meaning must remain unmapped or `unclear`;
  it must not be inferred.

## 6. Failure Expectations

- Invalid JSON must fail validation.
- Unknown block ids must fail validation.
- Evidence-like fields in mapper output must be rejected or ignored before
  downstream use.
